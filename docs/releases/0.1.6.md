# v0.1.6

发布日期：2026-11-25。

修复官方历史尚未完整回填时，将 HA 接入后的部分观察水量显示为“用水总量”的问题。

## 总量完整性

- 官方出水历史回填完成且每条记录都有确认水量前，“用水总量”显示未知。
  已确认同步为空历史时显示 0；记录缺失水量时不将缺失值当作 0。
- 本地观察累计继续持久化，保留在 `local_observed_total_ml` 和 `local_observed_count` 属性中。
- 已完整同步的总量在设备离线或后续同步失败时仍可读取，属性保留上次同步时间及失败原因。
- 新增 `sync_status`、`staged_count`、`server_total`、`sync_error` 等属性，显示回填进度与问题。
  `missing_volume_count` 表示缺少水量的记录数，`total_volume_complete` 表示记录和水量是否完整。
- 部分回填缓存恢复到仅 LAN 模式后，状态显示云端已停用，保留回填进度；恢复自动模式后继续同步。
- `oldest_record_date`、`newest_record_date` 给出缓存最早、最晚记录的毫秒时间戳，便于核对日期范围。

## 与 App“所有记录”的关系

重新核对官方 P30 模板确认，“泡奶周报 → 所有记录”使用当前集成已采用的 `type=3` 接口和
`waterOutput` 字段，没有宝宝或奶瓶筛选。集成从时间戳 0 开始分页查询，不限制为当前周或最近 50 条。
最近 50 条仅为实体属性展示范围，完整缓存用于计算总量。

这次修复纠正部分累计的显示与完整性判断，没有新增另一条历史接口。官方服务的保留期限、实际查询限制
及其他机型兼容性仍未确认，不能把回填完整理解为已获得设备整个寿命的全部出水。

## 升级

通过 HACS 更新后重启 Home Assistant。手动安装请将 `bololo-0.1.6.zip` 解压到 HA 配置目录，
整体替换 `custom_components/bololo/` 后重启。`bololo-smart-control.zip` 为 HACS 布局。
已有配置和历史缓存保留，无需删除集成；尚未完成回填的总量可能从旧版数字变为未知。
仅 LAN 模式且无完整官方缓存时，总量也显示未知，可在属性中查看本地累计。

## 验证

273 项自动化测试、Ruff 检查和格式检查通过。新增用例覆盖缺失水量、真实空历史、同步进度、
缺少设备序列号、离线缓存及真实 HA 的未知状态。跨多年用例模拟 1055 条记录、11 页，
第一批读取 1000 条后重启续传，核验全部水量合计 116050mL，展示明细仍限制为 50 条。

这些是离线协议与回归验证，未用真实账号核对 App 记录或进行设备联调。
详见 [README](../../README.md#出水烧水与消烘记录) 和 [来源分析](../../analysis/HISTORY.md)。
