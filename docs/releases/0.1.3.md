# v0.1.3

修复图形验证码页面没有图片，导致无法继续请求短信的问题。

## 原因与修复

v0.1.2 将图形验证码作为 `data:image/...` 放在配置页说明中。用户确认刷新翻译后出现中文标签，
图片仍不可见，因而无法完成图形验证。具体浏览器/HA 版本的图片限制仍待运行环境确认。
输入短信验证码到图形验证步骤也无法通过。

本版改为 HA 本地 HTTP 图片地址，使用 HA 认证及仅针对单张图片、5 分钟有效的签名链接。
图片仅保存在内存中，刷新挑战或发码成功时移除旧图片，超时自动清理；不写入公开 www 目录。
限制图片大小和缓存数量，并禁止 SVG 等主动内容。

图形验证码错误或过期时会显示提示并更新图片。短信页面同时填写验证码并勾选重发时，优先验证已有验证码；
需要重发时先清空验证码，再勾选重新发送。LAN 优先和会话续期行为保持不变。

## 升级与配置

通过 HACS 升级并重启 HA，随后强制刷新浏览器或使用无痕窗口，重新开始未完成的配置。
手动安装请使用 `bololo-0.1.3.zip` 整体替换 `custom_components/bololo/`；HACS 布局包为 `bololo-smart-control.zip`。

出现“图形验证码”时先输入图片里的字符；随后再输入手机收到的短信验证码。二者是两个不同的步骤。
图片链接 5 分钟后失效，超时请重新开始配置。已有成功配置的账号无需删除。

## 验证

167 项自动化测试通过，Ruff 检查和格式检查通过。新增测试经过真实 HA 配置流程管理器，覆盖图形验证、
短信错误与成功登录，并经 HA 实际 HTTP 认证中间件验证：签名链接可读图、无签名返回 401、
跨图片篡改路径返回 401、图片过期或撤销返回 404、缓存数量受限。

前端与协议核对记录在 [分析文档](https://github.com/maycode0-0/bololo-smart-control/blob/main/analysis/SMS_LOGIN.md)。
未使用用户真实账号发短信或代填图形验证码；手机收码、Z60/P30 真机行为仍需实际环境确认。
